== Introduction

This Domain Standard defines the layout rules and schema requirements specific 
to human-readable JSON files inside ODISC.

These rules build directly upon the data naming rules established in 
xref:../DS-011-300/index.adoc[DS-011-300] to ensure that our text files stay consistent and predictable.

== Functional Requirements

=== Whitespace and Layout
Minified formats should be used in transit for production network traffic. 

Pretty-printed formats used in documentation or logs shall use 2 spaces per 
indentation level. Tab characters (`\t`) shall not be used for indentation.

=== Handling Empty and Null Values
If an optional field has no value, the key should be completely omitted from 
the payload rather than explicitly set to `null`. Empty collections shall 
be represented as an empty array literal `[]` instead of `null`.

=== Dialect Specification
Every schema shall declare its meta-schema version using the `$schema` keyword. 
The standard dialect for development is "Draft 2020-12".

=== Schema Metadata
The root object shall contain a unique `$id` URL pointing to its canonical, 
internally hosted location. The root object shall include a brief, descriptive 
`title` and `description` to document its domain purpose.

=== Dependency and Isolation Constraints
All schemas shall be fully self-contained or reference exclusively in-house 
schemas using relative local paths or internal corporate domain URLs. External, 
third-party internet schemas shall not be imported or referenced.

=== Strict Validation and Composition Behavior
Single, standalone object schemas shall explicitly set 
`"additionalProperties": false` to prevent unexpected fields from being 
injected. 

Multi-layered or polymorphic schemas (e.g., combining a shared race event 
base with specific telemetry data) shall use `"unevaluatedProperties": false` 
at the root composition level instead of `additionalProperties`.

All elements within an `array` schema shall explicitly specify their valid 
type using the `items` keyword.
